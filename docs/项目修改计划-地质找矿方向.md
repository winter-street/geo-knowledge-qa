# 项目修改计划：从国土规划到地质找矿方向

> **日期**：2026-07-09
> **原因**：指导老师指出当前项目空间属性不足，建议转向地质找矿方向，结合文本知识抽取与空间地理数据，实现知识图谱+空间可视化问答。
> **原则**：最大程度复用现有技术架构（Vue 3 + Express + Flask + Neo4j + TF-IDF），重点改造数据层、知识图谱 Schema、地图交互和问答提示词。

---

## 一、目标重新定位

| 维度 | 原方向（国土规划） | 新方向（地质找矿） |
|------|-------------------|-------------------|
| 领域 | 城镇开发边界、用地分类、规划指标 | 地层、构造、矿产、地质年代、岩性 |
| 知识源 | 政策 PDF（46+35页） | 地质志/调查报告/区域地质总结 PDF |
| KG 节点类型 | LandUse、Concept | Rock（岩石）、Structure（构造）、Mineral（矿产）、Era（地质年代）、Region（空间区域） |
| 空间数据 | 无（仅 AMap 底图占位） | 地质矢量图（GeoJSON）+ 矿产点位 + 断层线 |
| 问答输出 | 纯文本 + 来源引用 | 文本 + 来源引用 + 地图标注（如"受断裂带控制的铁矿分布"） |
| 核心创新 | RAG+KG 双路检索 | **文本语义 + 空间语义双通道融合** |

---

```
阶段一（1-2周）：地质数据准备 + KG Schema 重构
    ↓

    ↓

```

### 3.2 地质知识图谱 Schema 设计

**新节点类型：**

```cypher
-- 岩石节点
(:Rock {
  name: "花岗岩",          -- 岩石名称
  category: "岩浆岩",       -- 大类：岩浆岩/沉积岩/变质岩
  subcategory: "酸性侵入岩", -- 亚类
  mineral_composition: "石英,长石,云母", -- 矿物组成
  texture: "中粗粒",       -- 结构
  age_era: "燕山期"        -- 所属地质年代
})

-- 构造节点
(:Structure {
  name: "湘江断裂带",
  category: "断裂",         -- 断裂/褶皱/韧性剪切带
  orientation: "NE-SW",    -- 走向
  dip: "NW 60°",           -- 倾向/倾角
  length_km: 120,          -- 长度
  description: "..."
})

-- 矿产节点
(:Mineral {
  name: "黄沙坪铅锌矿",
  type: "铅锌矿",           -- 矿产类型
  genetic_type: "热液充填型", -- 成因类型
  host_rock: "石灰岩",     -- 赋矿围岩
  era: "燕山期",           -- 成矿时代
  reserves: "大型",        -- 规模
  location_lat: 25.8,     -- 纬度（如果有坐标）
  location_lng: 112.7,    -- 经度
  description: "..."
})

-- 地质年代节点
(:Era {
  name: "燕山期",
  rank: "期",              -- 宙/代/纪/世/期
  age_range: "205-135 Ma",
  parent_era: "侏罗纪-白垩纪"
})

-- 空间区域节点（连接文本与地图）
(:Region {
  name: "湘南成矿带",
  type: "成矿带",          -- 成矿带/矿集区/工作区
  bbox: "25.5,112.0,27.0,114.0",  -- 边界框
  geo_json_file: "xiangnan.json"   -- 关联的空间数据文件
})
```

**新关系类型：**

| 关系 | 起点 → 终点 | 含义 |
|------|------------|------|
| `HOSTED_IN` | Mineral → Rock | 矿产赋存于某种岩石 |
| `CONTROLLED_BY` | Mineral → Structure | 矿产受构造控制 |
| `FORMED_IN` | Mineral → Era | 矿产形成于某地质年代 |
| `BELONGS_TO` | Rock → Era | 岩石属于某地质年代 |
| `LIES_IN` | Rock/Structure/Mineral → Region | 实体位于某空间区域 |
| `ASSOCIATED_WITH` | Mineral → Mineral | 矿产共生/伴生关系 |
| `CUTS` | Structure → Rock | 构造切穿岩层 |
| `REFERENCES` | Chunk/Document → Entity | 文本引用实体（保留） |

### 3.3 实体提取脚本改造

**extract_geology.py（替代 extract_landuse.py + extract_concepts.py）：**

```
输入：地质 PDF 的 chunks
方法：
  1. LLM（DeepSeek）按 chunk 提取结构化地质实体
  2. 输出 JSON 格式：{rocks[], structures[], minerals[], eras[], relations[]}
  3. 去重合并（同名实体归一化）
  4. 用已有词典进行规则验证（如已知矿产名称列表）
```

**Prompt 设计要点（LLM 提取）：**
- 要求识别岩石名、构造名、矿产名、地质年代
- 要求提取实体间关系（赋存、控矿、年代归属等）
- 要求标注来源 chunk（可溯源）
- 输出结构化 JSON

### 3.4 Neo4j 写入改造（write_neo4j.py）

- 删除旧数据（CLEAR ALL）
- 创建新节点约束（按新 Schema）
- 批量写入节点 + 关系
- 建立 Text Chunk ↔ Entity 的引用边（保留 RAG 溯源性）

### 3.5 后端 KG 查询改造（`backend/src/services/kg.ts`）

当前 `searchEntities()` 用 `CONTAINS` 模糊匹配。改造后：

- 增加地质实体类型过滤（WHERE n:Rock OR n:Structure OR n:Mineral OR n:Era）
- 增加空间区域查询（WHERE n:Region）
- 子图查询按新关系类型返回
- 新增接口：`GET /api/kg/spatial?region=xxx` 返回区域内所有实体（供地图层用）

## 四、阶段二：空间数据集成

### 4.1 地质图矢量化（C 同学）

**输入：** 指导老师提供的地质图（栅格/图片）→ 选取一小块区域矢量化

**矢量化方法（按优先级）：**
1. **QGIS 手动矢量化**（最可靠）：在地质图上描出断层线、矿点、岩层边界，导出 GeoJSON
2. **如果老师提供 shapefile**：直接用 QGIS 导出 GeoJSON
3. **简化策略**：只矢量关键要素——
   - 主要断裂带（线要素）
   - 已知矿产点（点要素）
   - 主要岩层分布（可选，多边形要素，工作量较大）

**产出文件：**
```
ml-service/data/
├── faults.geojson        # 断裂带线要素
├── minerals.geojson      # 已知矿产点位
├── strata.geojson        # 岩层分布（可选）
└── work_area.geojson     # 工作区边界
```

## 五、阶段三：空间问答联调

### 5.1 问答接口改造（`backend/src/routes/qa.ts`）

**当前流程：** user question → RAG + KG 并行 → LLM 生成 → 返回文本 + sources + kgContext

**改造后流程：**

```
user question
    ↓
┌── 意图识别（新增）─────────────────────┐
│ 判断问题是否包含空间查询意图            │
│ 关键词：在哪里/分布/哪些区域/图上/断裂带 │
└──────────────────────────────────────┘
    ↓
┌── 三路并行检索 ────────────────────────┐
│ ① RAG: jieba + TF-IDF → Top-K chunks  │  ← 保持
│ ② KG:  Neo4j 实体搜索 + 关系链         │  ← 保持（新 Schema）
│ ③ 空间: 实体名 → GeoJSON 坐标查询      │  ← 新增
└──────────────────────────────────────┘
    ↓
LLM 生成回答（新 Prompt，地质领域）
    ↓
返回: { answer, sources, kgContext, spatialFeatures[] }  ← 增加空间数据
```

**SSE 流式新增事件类型：**
```
data: {"type": "meta", "ragCount": 5, "kgCount": 3, "spatialCount": 4}
data: {"type": "spatial", "features": [...]}    ← 新增：在回答开始前发送空间数据
data: {"type": "chunk", "content": "根据..."}
data: {"type": "done", "sources": [...], "kgContext": [...]}
```

你是地质找矿知识助手，基于区域地质调查报告、矿产地质资料回答用户问题。

回答要求：

## 八、技术风险与降级方案

| 风险 | 影响 | 降级方案 |
|------|------|---------|
| 地质 PDF 质量差（扫描版/无文本层） | 无法提取文本 | ① OCR 预处理 ② 优先用老师提供的电子版地质志 |
| 地质图矢量化工作量大 | 空间功能无法演示 | ① 只矢量 5-10 个矿点 + 2-3 条断层 ② 用随机模拟点位演示技术链路 |
| LLM 地质实体提取准确率低 | KG 质量差 | ① 用规则词典辅助 ② 人工审核 Top-50 高频实体 |
| 地质知识专业性强，团队理解不足 | 图谱关系错误 | ① 聚焦基础关系（赋矿岩石、控矿构造、成矿时代） ② 请老师审核 schema |
| 矿点坐标数据不全 | 地图标注为空 | ① 从文献中手动提取 ② 使用公开矿产地数据库（如全国矿产地数据库） |
| TF-IDF 对地质专业术语分词不准 | RAG 检索效果差 | ① jieba 加载地质专业词典 ② 升级为 BERT 语义检索（终期） |
