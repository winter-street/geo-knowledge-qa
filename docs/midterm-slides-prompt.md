## 全局风格

- 模式：电子杂志 × 电子墨水
- 配色：暖灰 Ink 色阶 (#1A1A2E ~ #E2DFD6) + forest green #2E7D5B 主色 + institutional blue #1E3A5F 强调
- 字体：Source Serif 4 标题 + Inter 正文，CJK 回退 PingFang SC / Microsoft YaHei
- 圆角：最大 6px，禁止胶囊形
- 阴影：极简，无彩色阴影/发光
- 翻页：横向滑动
- 节奏：根据内容切换全页大字报 / 左右分栏

## 第 4 页：双路检索详细设计（左右分栏）

### 口播文案（1.5 分钟）
"双路检索是我们系统的核心设计。传统 RAG 只做文本向量搜索，得到的是孤立的知识片段。我们增加了知识图谱路径——从 Neo4j 中查实体间的语义关系，补全了上下文关联。具体流程是：用户问题进来后，RAG 路径用 jieba 分词并向量化，在 SQLite 中做余弦相似度检索，取 Top-5 chunks。KG 路径用 Cypher 的 CONTAINS 关键词匹配，提取多跳关系链。两路结果合并后拼接成 prompt 送给 DeepSeek，由大模型综合生成回答，前端同步展示来源引用卡和 KG 关系标签。这里 TF-IDF 是我们第一阶段的选型——零配置、零网络依赖，答辩现场无需 GPU。终期会升级到 BERT 语义检索。"

## 第 5 页：知识图谱构建详细设计（左右分栏）

### 口播文案（1.5 分钟）
"知识图谱是我们相比普通 RAG 系统最大的差异化。我们用了两种互补的提取策略。针对用地分类指南——这份文档天然有编码层级：2位编码是大类、4位是中类、6位是小类——我们直接用正则规则提取，100% 准确，产出了 137 个 LandUse 节点。针对编制指南——政策文本没有固定格式——我们用 DeepSeek 大模型分段提取规划概念和关系，产出约 213 个 Concept 节点。为了保证图谱质量，我们设计了三道语义过滤规则：去掉含数字编码的碎片、去掉'及其''现行'等非名词开头、去掉两个概念粘连在一起的名称。最终 Neo4j 中存储了 350 多个节点、490 多条关系，每一条关系都标注了中文显示名：管控、约束、属于、引用。"

### 视觉内容：左侧 55% 流程图 + 过滤规则，右侧 45% Neo4j 截图占位 + Schema

**左侧：双路构建流程**
```
PDF 用地分类指南 → 正则匹配编码层级 → LandUse 137 节点
PDF 编制指南 → 分段 → DeepSeek 提取 → 3道过滤 → Concept 213 节点
                                    ↓
                          Neo4j (350+ 节点, 490+ 关系)
                                    ↓
                       GraphView SVG 力导向图可视化
```

三条过滤规则（小卡片样式）：
A. 含 4 位以上连续数字 → 丢弃（如"工矿用地10010"）
B. 非名词短语开头 → 丢弃（如"及其1990版分类思路"）
C. 两概念粘连 → 丢弃（如"物流仓储用地11仓储用地"）
