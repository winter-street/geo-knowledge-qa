# 问答驱动地图功能编排设计

日期：2026-07-13

## 目标

系统继续以智能问答为主入口。用户不需要先进入地图页逐个点击工具，而是直接用自然语言描述区域、矿种、距离、年代和分析目标。后端在生成地质回答的同时输出经过程序校验的地图执行计划，前端自动完成空间查询、过滤、定位和分析，并在需要时把完整状态带入地图页。

该能力不是让大模型直接控制页面。LLM 负责解释检索和分析结果；地图动作由确定性空间语义解析、白名单协议和前端执行器共同控制。

## 用户体验

### 默认行为

- 普通空间问题在问答页内嵌地图自动执行，不强制离开回答页面。
- 问答消息显示本次已经执行的地图动作，例如“攀西区域查询、钒钛磁铁矿筛选、有利度排序”。
- 复杂分析在问答页展示摘要，并提供“完整地图”入口。进入地图页后保留查询结果、筛选条件和分析模式。
- 用户明确说“打开地图”“进入地图分析”时，系统自动跳转地图页并继续执行完整计划。
- “导出”只准备数据并突出显示相应按钮，不未经确认自动下载文件。
- 用户可以清除本次自动分析，恢复地图默认状态。

### 示例

| 用户问题 | 自动地图行为 |
|---|---|
| 显示攀西钒钛磁铁矿 | 查询攀西、筛选钒钛磁铁矿、定位结果范围 |
| 显示攀西断裂 10 公里范围内的高有利矿点 | 查询、构造邻近筛选、有利度模式、距离排序 |
| 查看全国矿产热力分布 | 全国查询、开启热力图、定位十个演示成矿区 |
| 播放全国矿产时空演化 | 全国查询、进入年代时间轴模式、打开完整地图 |
| 对比攀西和东天山的钒钛磁铁矿有利度 | 双区域筛选、评分模式、区域对比摘要 |
| 用 10 公里网格预测攀西钒钛磁铁矿靶区 | 网格预测、靶区圈定、打开完整地图 |
| 打开地图，只看晚二叠世矿点 | 年代过滤、自动跳转、调整可视范围 |
| 导出当前空间分析结果 | 保留当前可见结果，提示 GeoJSON/CSV 导出操作 |

## 地图动作协议

后端问答响应新增 `mapPlan`：

```ts
interface MapPlan {
  id: string
  version: 1
  title: string
  autoExecute: boolean
  openFullMap: boolean
  actions: MapAction[]
  warnings: string[]
}
```

第一版动作类型：

```ts
type MapAction =
  | { type: 'query'; question: string }
  | { type: 'filter-region'; regions: string[] }
  | { type: 'filter-era'; eras: string[] }
  | { type: 'filter-entity'; entityTypes: GeoEntityType[] }
  | { type: 'set-result-mode'; mode: 'query' | 'score' }
  | { type: 'buffer'; radiusKm: number; anchorName?: string; targetType?: GeoEntityType }
  | { type: 'heatmap'; enabled: boolean }
  | { type: 'timeline'; mode: 'all' | 'single' | 'play'; era?: string }
  | { type: 'compare-regions'; regions: string[] }
  | { type: 'grid-prediction'; gridSizeKm: 5 | 10 | 20; minimumScore?: number }
  | { type: 'fit-bounds' }
  | { type: 'suggest-export'; format: 'geojson' | 'csv' }
```

动作按数组顺序执行。`query` 必须先产生空间结果，过滤和分析动作才能消费结果；`fit-bounds` 在数据和图层更新完成后执行。执行器对重复动作去重，对互斥动作采用后出现者覆盖前者。

## 后端规划器

新增独立的地图计划服务，消费现有 `SpatialQueryInterpretation` 和 `SpatialAnalysis`，输出 `MapPlan`。规划规则包括：

- 区域、矿种、年代和实体类型生成查询及过滤动作。
- “有利度、潜力、靶区、预测”生成评分模式。
- 明确距离和“附近、周边、缓冲区”生成缓冲动作。
- “热力、密集区、聚集区”生成热力图动作。
- “时空、演化、时间轴、播放”生成时间轴动作。
- 两个及以上明确区域和“对比、比较、差异”生成区域对比动作。
- “网格”与合法网格大小生成网格预测动作；未给大小时默认 10 公里。
- “打开地图、进入地图、完整地图”设置 `openFullMap=true`。
- “导出、下载”生成导出建议动作。

地图计划不依赖 DeepSeek 返回 JSON。后端先根据规则生成计划，再把计划摘要作为上下文交给 LLM，使文字回答与实际地图行为保持一致。

## 问答数据流

```text
用户问题
  -> 空间语义解析
  -> RAG / KG / 空间检索
  -> 空间分析结果
  -> 地图计划生成与校验
  -> SSE meta(mapPlan + spatialData + spatialAnalysis)
  -> LLM 流式文字回答
  -> SSE done(权威地图计划与数据)
```

`meta` 阶段发送地图计划，使地图可以在回答生成期间开始加载。`done` 阶段返回最终计划；若与 `meta` 不同，前端按相同 `id` 更新，不重复执行已经成功的动作。

非空间问题不返回 `mapPlan`。低相关度问候响应也不生成地图动作，避免无关问题误触发演示数据。

## 前端状态与执行器

新增 Pinia `spatial-task` Store，统一保存：

- 当前地图计划及执行状态；
- 原始空间数据和空间分析；
- 区域、年代、实体过滤条件；
- 查询模式与有利度模式；
- 缓冲参数和结果；
- 热力图与时间轴状态；
- 区域对比状态；
- 网格与靶区结果；
- 导出建议、警告和失败动作。

Store 使用 `sessionStorage` 保存当前任务，使问答页跳转地图页和浏览器刷新后仍可恢复；不写入长期问答历史，避免旧对话中的地图计划覆盖新任务。

地图动作执行器分为两级：

1. **问答页执行器**：执行查询、过滤、有利度模式、简单缓冲摘要、区域对比摘要和定位。
2. **完整地图执行器**：执行全部动作，包括热力图、时间轴、复杂缓冲渲染、网格预测、靶区圈定和导出准备。

`QaView` 和 `MapView` 不互相调用组件内部函数。二者订阅同一个 Store，并通过共享的纯状态转换函数解释动作。高德地图实例仍由各页面自行管理，地图覆盖物渲染根据 Store 状态更新。

## 网格预测与靶区圈定

网格预测作为地图动作协议中的高级动作，而不是独立入口。用户通过问答提出“用 10 公里网格预测攀西钒钛磁铁矿靶区”后触发。

全国查询不铺满全国范围，只在当前十个演示成矿区的包围范围内生成网格；区域查询在对应区域边界及小范围外扩内生成。网格数量设置上限，超过上限时要求增大网格尺寸。

每个网格按 100 分计算演示有利度：

| 因子 | 分值 | 计算依据 |
|---|---:|---|
| 构造邻近度 | 40 | 网格中心或内部矿点到最近构造线的距离 |
| 矿化点密度 | 25 | 网格及相邻网格内的矿点数量和密度 |
| OWL/KG 证据 | 20 | 网格内实体携带的推理类别和知识关系证据 |
| 地质条件一致性 | 15 | 主导年代、岩性、矿床类型与查询条件的一致程度 |

相邻且得分不低于默认阈值 85 的网格按连通区域分组，生成“演示靶区 A、B、C”。输出包括面积、网格数、平均分、最高分、主要矿种、主导年代和四项评分依据。结果必须显示“规则模型与合成坐标演示，不作为实际勘查结论”。

## 安全与边界

- 只执行协议白名单内的动作和字段，不执行 LLM 生成的代码、URL 或任意函数名。
- 缓冲半径限制在 0.1 至 1000 公里。
- 网格尺寸只允许 5、10、20 公里。
- 区域、年代和实体类型必须来自后端已识别值或现有结果元数据。
- 全国网格数量设置硬上限；超限时返回可读警告，不阻塞文字回答。
- 导出、文件下载和页面跳转属于用户可感知副作用，只有明确意图或最终点击确认时执行。
- 无数据、动作不支持或地图 SDK 不可用时，保留文字回答和列表兜底。
- 所有 Mock 坐标、规则评分、网格和靶区均携带 `isMock/demo` 标记。

## 错误处理

- 单个动作失败不终止后续无依赖动作；执行结果记录 `success/skipped/failed`。
- 查询失败时，所有依赖空间数据的动作标记为 `skipped`。
- 旧版本或无法解析的地图计划退化为普通 `spatialData` 点线展示。
- `meta` 和 `done` 计划通过 `id + version` 去重。
- 页面跳转后找不到任务时，地图页显示默认状态，不使用旧缓存猜测。
- 前端对失败动作显示简短状态，后台日志记录具体错误和参数。

## 日志与可解释性

问答日志增加地图计划摘要：计划 ID、动作类型、成功数、失败数、是否跳转完整地图。消息区域显示本次自动执行的动作，不显示内部函数名。

网格和靶区点击详情必须列出每项因子的分数、上限和证据。原始 Neo4j 事实与 OWL 推理证据继续分开标记。

## 测试与验收

### 后端测试

- 空间问题生成正确动作顺序。
- 非空间问题不生成计划。
- 非法距离、网格和未知实体被拒绝或修正。
- 对比、时间轴、热力和导出意图不互相误判。
- SSE `meta` 与 `done` 返回相同计划 ID。
- 网格评分、阈值分组和靶区统计稳定可复现。

### 前端测试

- Store 按顺序执行、去重并记录状态。
- 问答页只执行支持的动作，复杂动作等待完整地图。
- 跳转地图页后状态完整恢复。
- 切换对话不会自动执行旧任务。
- 地图 SDK 失败时仍显示空间列表和动作摘要。
- 导出建议不会自动触发浏览器下载。

### 人工验收

依次执行目标示例问题，检查文字回答、问答内嵌地图、完整地图状态、自动动作摘要、日志和演示声明一致。重点演示“用 10 公里网格预测攀西钒钛磁铁矿靶区”，从自然语言问题一直到网格、靶区和可解释因子详情。

## 实施顺序

1. 定义共享类型和地图计划纯规则生成器。
2. 在普通与 SSE 问答响应中返回 `mapPlan`。
3. 建立 `spatial-task` Store、会话级恢复和动作状态机。
4. 接入问答页现有点线地图与动作摘要。
5. 让完整地图消费任务并驱动现有查询、过滤、评分、热力、时间轴和区域对比。
6. 实现网格预测和靶区圈定动作。
7. 补充导出准备、日志、自动化测试和人工演示验证。
