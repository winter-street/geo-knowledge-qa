# 地质调查 Agent 性能与效果评测设计

日期：2026-08-05

## 1. 目标

为升级后的地质知识图谱与 RAG 调查 Agent 建立可重复、可追踪且不泄露真实数据的评测基线。评测覆盖回答效果、检索质量、Agent 决策、多轮任务、端到端延迟、SSE 响应、并发承载、资源占用和故障降级。

本轮交付止于评测工具、正式基线和瓶颈报告。业务性能优化在基线冻结后单独实施，避免评测开发与业务调参相互污染。

本设计不涉及 GPU、CUDA、推理引擎、分布式训练或模型服务内部优化。DeepSeek 是外部服务，只评估本系统观察到的端到端表现，不据此声明底层模型推理性能。

## 2. 设计原则

- 复用现有 TypeScript 评测 Schema、指标计算和私有运行适配器，不引入第二套主评测框架。
- 将本地系统承载能力与真实 DeepSeek 网络表现分开测量。
- 同一道题运行 Direct、RAG、KG、Hybrid、Agent 五种模式，形成可比较的消融实验。
- 自动裁判只作辅助；正式回答质量结论必须经过匿名人工盲审。
- 私有输入与原始输出不进入公开报告，不提交真实问题、回答、标题、证据、坐标或凭据。
- 第一次正式运行冻结为 `baseline-v1`，后续评测只使用相同数据快照、配置和指标口径进行回归比较。

## 3. 当前评测缺口

- 当前合成用例把不同问题分配给不同模式，不能直接比较五种模式的相对效果。
- Direct 路由现有日志从检索完成后开始计时，遗漏检索和重排时间。
- 当前 SSE 在服务端缓存完整模型回答后才发送正文，首个正文时间接近完整生成时间。
- 现有结果只有总延迟和工具延迟，缺少检索、重排、规划、LLM、校验和持久化的统一阶段计时。
- 缺少并发负载、资源采样、客户端中断和依赖故障的自动化测试。
- 公开合成报告只能证明评测器计算正确，不能作为真实模型性能结论。

## 4. 三层测试架构

### 4.1 公开合成 CI 层

继续使用现有 80 道单轮题和 20 组三轮对话，验证：

- Schema 和开发集/测试集隔离；
- 指标计算与阈值判断；
- JWT、JSON、SSE 和多轮会话协议；
- 报告脱敏和敏感信息扫描；
- 模型桩超时、错误码和中断行为。

该层必须确定性运行，不访问真实文档、Neo4j 数据和外部模型。输出明确标记为 `synthetic-harness-validation`，不得用作模型效果声明。

### 4.2 本地可重复性能层

使用私有 Flask/Neo4j 和 OpenAI 兼容模型桩。模型桩支持配置首 token 延迟、token 间隔、固定回答、401、429、500、连接断开和超时。

该层用于测量本地 Node.js 编排、检索、图谱、SQLite、SSE 和多轮状态性能。所有正式负载运行在独立后端端口和独立应用状态数据库中，不修改当前用户会话或业务日志。

### 4.3 真实端到端验收层

使用私有留出题集、私有知识库和 DeepSeek。该层只采用低并发，报告用户实际观察到的端到端延迟、错误率和回答质量。

远程 API 延迟受网络、供应商负载和限流影响，只报告分布和测试条件，不设置武断的绝对延迟合格线。

## 5. 测试数据与实验矩阵

### 5.1 私有数据集

- 80 道单轮题：60 道有证据题、20 道拒答题。
- 20 组三轮对话：开发集 10 组、测试集 10 组。
- 单轮题按 40/40 划分开发集和测试集，每部分保持 30 道有证据题和 10 道拒答题。
- 开发集与测试集的实体、文档、区域和构造标识不得重叠。
- 每道有证据题标注相关文档 ID、可接受引用 ID、目标实体 ID、目标意图和预期工具。
- 每道拒答题明确记录知识库中不存在的目标事实。
- 私有数据集使用不可逆样本 ID；公开报告只使用样本 ID、数据快照哈希和聚合指标。

### 5.2 五模式消融

测试集每道单轮题依次运行：

1. `direct`：不提供 RAG/KG 证据；
2. `rag`：只允许文档检索；
3. `kg`：只允许图谱查询；
4. `hybrid`：按现有混合检索策略执行；
5. `agent`：允许规划、工具调用、记忆和证据校验。

这里的评测模式 `direct` 表示“裸模型基线”，由私有评测适配器直接调用同一 LLM，不经过检索。它不同于接口参数 `agentMode: "direct"`；后者仍可配合 `retrievalMode: "rag" | "kg" | "hybrid"` 使用。

同一模式在同一问题上默认只执行一次正式质量评测，降低真实 API 成本。温度、模型、Top-K、重排配置和数据快照必须写入运行清单。

多轮测试只运行 Agent 模式，每组对话使用独立用户和会话 ID，三轮按顺序执行，不跨会话共享活动实体。

## 6. 指标口径

### 6.1 检索与回答效果

- `Recall@5`：相关文档在前 5 个检索结果中的召回比例。
- `MRR@10`：首个相关文档在前 10 个结果中的倒数排名均值。
- 引用精确率：输出引用中能匹配人工接受证据的比例。
- 事实不支持率：无证据支持的事实断言数除以全部事实断言数。
- 无证据错误作答率：拒答题中仍给出事实性答案的比例。
- 回答任务完成率：人工盲审判断回答是否解决问题。
- 五模式差值：每项指标同时报告绝对值、相对 Direct 的差值和 95% bootstrap 置信区间。

`Recall@5` 和 `MRR@10` 只对实际执行文档检索的 RAG、Hybrid 和 Agent 分别计算；Direct 和 KG 标记为不适用，不以零值参与平均。

### 6.2 Agent 指标

- 意图识别准确率；
- 工具集合完全匹配率；
- 工具参数正确率；
- 实体链接 Top-1 准确率；
- 多轮任务成功率：三轮全部成功才计为该组成功；
- 工具执行成功率和超时率；
- 平均工具数与冗余工具率；
- 规划遵循率：实际工具调用是否符合已发布计划。

### 6.3 性能指标

- HTTP 总响应时间 P50、P95、P99；
- TTFB：收到 HTTP 响应头的时间；
- SSE 首事件时间：收到首个合法 SSE 事件的时间；
- SSE 首正文时间：收到首个非空 `chunk` 的时间；
- SSE 完整时间：收到 `done` 或连接结束的时间；
- 吞吐量、成功率、HTTP 错误率、SSE 协议错误率和超时率；
- 检索、重排、意图、实体链接、规划、工具、LLM、事实校验、持久化分段耗时；
- Node、Flask、Neo4j 进程的 CPU、工作集内存和峰值；
- 稳态测试结束后 60 秒的内存回落比例。
- 真实 API 的 LLM 调用次数、输入/输出 token 数和按运行时价格表计算的费用估算；供应商未返回 usage 时明确标记为不可用。

所有时延使用单调时钟采集。P95/P99 只在样本量足够时报告；样本少于 100 时 P99 标记为参考值。

## 7. 负载场景

### 7.1 本地正式压测

场景：

- `agentMode: "direct" + retrievalMode: "hybrid"` JSON 单轮；
- Agent JSON 新会话；
- Agent SSE 新会话；
- Agent 三轮连续会话。

负载参数：

- 并发级别：1、5、10、20；
- 每档预热 15 秒，不计入报告；
- 每档稳态 60 秒；
- 每个场景重复 3 次；
- 请求问题从私有测试池轮转，虚拟用户使用独立 JWT 和会话 ID；
- 场景之间冷却 30 秒，正式套件结束后观察内存 60 秒。

### 7.2 真实 DeepSeek 测试

- 40 道私有测试集单轮题运行五模式，共 200 个正式单轮观察值；
- 10 组三轮对话运行 Agent，共 30 个多轮 turn；
- 另选 10 道分层代表题，在并发 1、2、5 下测试 Hybrid 和 Agent；
- 性能子集每个并发档重复 3 次；
- 遇到 429 时记录供应商限流，不自动提高并发；允许按 `Retry-After` 延迟一次后重试，重试结果和原始失败分别记录。

## 8. 计时与诊断接口

评测运行器为每个请求生成 `runId` 和 `requestId`。仅当本地环境显式启用 `PERF_TEST_MODE=true` 时，后端接受性能追踪头并在响应中返回诊断信息。

- 请求头：`X-Perf-Run-Id`、`X-Perf-Request-Id`；
- JSON 响应：增加可选 `performance` 字段；
- SSE：在 `done` 前增加可选 `performance` 事件；
- `performance` 只包含阶段名称、耗时、状态和计数，不包含问题、提示词、回答或证据文本；
- 非性能模式不返回该字段或事件，前端现有解析保持兼容。

统一阶段名称：`auth`、`retrieval`、`rerank`、`intent`、`entity_link`、`planning`、`tools`、`llm`、`grounding`、`persistence`、`total`。

Direct 和 Agent 路由必须从请求进入路由时开始总计时。工具 trace 继续保留每个工具的独立耗时，并与请求级阶段计时关联。

## 9. 故障与降级测试

使用独立临时后端、模型桩和可覆盖的依赖地址执行，不停止或修改当前私有服务。

- LLM：401、429、500、连接失败、首 token 超时、生成中断；
- Flask：连接失败、搜索超时、空结果、非法响应；
- Neo4j：连接失败、查询超时、空图谱；
- 重排：模型不可用和返回非法排序；
- SSE：客户端在 `meta` 后断开、首正文后断开、重复事件和无 `done`；
- 会话：后端重启后恢复、伪造会话 ID、跨用户访问同一会话 ID；
- 组合故障：RAG 不可用但 KG 可用、KG 不可用但 RAG 可用、LLM 不可用但证据可返回。

验收关注是否正确降级、是否泄漏内部错误或私有内容、是否遗留运行中会话、是否产生未捕获异常，而不是要求所有故障都返回 200。

## 10. 验收门槛

### 10.1 效果门槛

- RAG `Recall@5 >= 80%`；
- RAG `MRR@10 >= 70%`；
- 意图识别准确率 `>= 90%`；
- 工具选择准确率 `>= 90%`；
- 实体链接 Top-1 准确率 `>= 85%`；
- 多轮任务成功率 `>= 80%`；
- 引用精确率 `>= 90%`；
- 无证据错误作答率 `<= 10%`；
- 事实不支持率 `<= 35%`；
- 相对 Direct 的事实不支持率至少下降 20 个百分点。

### 10.2 本地性能门槛

- 并发 20 时请求错误率 `<= 1%`；
- 并发 20 时超时率 `<= 1%`；
- 并发 10 的 P95 不超过并发 1 的 2.5 倍；
- 可控模型桩下 SSE 首个 `meta` 事件 `<= 1 秒`；
- 可控模型桩下 SSE 首个正文 `<= 2 秒`；
- 测试结束后工作集内存相对稳态起点增长 `<= 20%`；
- `baseline-v1` 建立后，相同场景 P95 回退不得超过 15%，错误率不得增加超过 1 个百分点。

真实 DeepSeek 延迟只设置可用性门槛：成功率 `>= 95%`，供应商明确返回的 429 单独报告，不混入本地服务错误率。绝对时延不作为首轮发布阻断条件。

真实 API 成功率以排除供应商明确 429 后的有效尝试数为分母，同时单独报告包含 429 的原始成功率，避免隐藏限流影响。

## 11. 报告与隐私

每次运行生成：

- `manifest.json`：Git commit、Node/Python/Neo4j 版本、配置摘要、数据快照哈希和模型标识；
- `observations.private.jsonl`：私有逐请求观察值，必须被 Git 排除；
- `summary.private.json`：完整私有聚合结果；
- `report.private.md`：完整瓶颈与失败样本报告；
- `summary.public.json`：不含原始内容的匿名聚合结果；
- `report.public.md`：可用于 README 和作品集的结论、图表数据和限制说明。

公开输出禁止包含：真实问题、回答、提示词、文档标题、证据原文、真实坐标、用户名、会话内容、API Key、Neo4j 凭据和原始异常堆栈。

敏感信息扫描必须作为报告生成的最后一步；扫描失败时不得生成可发布标记。

## 12. 开源参考的使用边界

- Ragas：借鉴 Context Recall、Context Precision 和 Faithfulness 的指标定义；
- DeepEval：借鉴 Tool Correctness、Argument Correctness、Task Completion 和 Step Efficiency；
- promptfoo：借鉴声明式实验矩阵、阈值和 CI 回归思想；
- k6：借鉴预热、稳态、分级并发和阈值模型；
- Langfuse：借鉴 trace/span 的阶段化可观测结构。

首轮不直接引入上述框架作为核心依赖。现有系统需要 JWT、多轮会话、私有数据脱敏和自定义 SSE 事件，轻量 TypeScript 运行器更易维护。后续如需团队协作的在线观测平台，再单独评估 Langfuse/OpenTelemetry。

## 13. 测试工具的模块边界

- 质量运行器：负责五模式矩阵、私有适配器和人工评审导出；
- 负载运行器：负责并发、SSE 客户端、重试和客户端计时；
- 模型桩：提供 OpenAI 兼容非流式/流式响应及故障脚本；
- 资源采样器：采集目标进程 CPU 和内存，不读取业务数据；
- 指标聚合器：负责分位数、置信区间、模式差值和阈值判断；
- 报告器：分别生成 private/public 输出并执行隐私检查。

模块之间只传递结构化观察值，负载运行器不负责指标解释，报告器不直接访问服务。

## 14. 测试与完成标准

- 单元测试验证分位数、bootstrap 置信区间、五模式覆盖、错误分类和隐私过滤；
- 集成测试验证 JWT、JSON、SSE、多轮会话、性能事件和模型桩；
- 契约测试验证非性能模式的现有响应不变；
- 故障测试验证所有第 9 节场景均产生预期状态且无未捕获异常；
- 完整本地压测能够一条命令运行并生成报告；
- 私有真实评测必须由显式命令启动，不能进入 CI；
- 全新克隆在无真实数据、无真实密钥时仍能运行公开合成评测；
- `baseline-v1` 报告明确列出通过项、失败项、瓶颈排序和下一轮优化建议；
- 旧版 30 题和 63.2% 数据不得写入新版基线或简历，除非报告明确标记为历史结果。

## 15. 默认假设

- 运行环境固定为 Node.js 22.18、Python 3.10 和 Neo4j 5.26.4；
- 测试机器为当前 Windows 开发机，正式报告记录 CPU、内存和操作系统信息；
- 本轮不修改检索算法、Prompt、Agent 规划或 SSE 业务行为；测试发现的问题进入后续优化计划；
- 正式运行前冻结私有测试集和数据快照，开发集可用于调试，测试集只在正式验收时运行；
- 本轮只新增设计、测试工具和报告，不自动提交、推送或创建 Pull Request。
