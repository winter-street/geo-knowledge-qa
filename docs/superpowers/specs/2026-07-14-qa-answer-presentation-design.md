# 问答回答与地图入口收敛设计

> 日期：2026-07-14
> 状态：设计已确认，待书面审阅

## 问题

当前问答页把正文、参考来源、本体推理、演示关系、知识图谱、空间分析、地图任务和第二个高德地图连续展示。一条普通地质问题因此可能占据数屏，并在回答带坐标时自动挂出固定高度 320px 的内嵌地图。

回答生成侧也在扩大问题：提示词要求列出关键地质实体，允许追加“现有资料还覆盖了以下方面”，并把普通问题命中的空间数据与演示 KG 关系一并交给 LLM。最终回答容易偏离问题、重复演示声明，并出现多个同级长段落。

## 目标

- 普通地质问答先给结论，只保留与问题直接相关的 2 至 4 个要点。
- 一条普通回答正文控制在约 300 至 500 个汉字；复杂空间任务可以按实际需要更长。
- 参考来源、本体推理和空间分析仍可查看，但默认不占用大段页面。
- 知识图谱保持现有查询、展开、全屏和样式，不改变本轮已修复的图数据逻辑。
- 问答页不再创建第二个高德地图实例，也不自动弹出或自动跳转地图。
- 空间结果统一通过一个“查看地图”按钮进入用户或管理员地图页。
- 删除“示例空间数据 1/3”开发入口及其专用 mock 注入代码。
- 演示关系提示只出现一次，且演示 KG 关系不能成为正文中的地质事实依据。

## 非目标

- 不删除独立地图页及其缓冲区、热力图、时间轴、区域对比、网格预测和导出功能。
- 不改变后端 RAG、KG、空间检索的并行执行方式。
- 不删除消息中保存的 `spatialData`、`spatialAnalysis` 或 `mapPlan`。
- 不修改知识图谱布局、节点样式、40 节点上限或全屏交互。
- 不重做整个问答页为标签页或抽屉式产品结构。

## 回答生成

### 输出结构

系统提示词和用户提示词统一要求：

1. 开头用 1 至 2 句话直接回答问题。
2. 仅在确有多个并列结论时使用 2 至 4 个无序要点；每个要点不超过 2 句。
3. 结尾最多使用 1 句总结，不再追加“关键地质实体”列表。
4. 不主动扩展与问题无关的岩体尺寸、矿段清单、围岩机制或空间统计。
5. 不使用“现有资料还覆盖了以下相关信息”作为扩写入口。
6. 不在正文重复参考来源、本体卡片、图谱组件或地图组件已经展示的信息。

普通问题以 300 至 500 个汉字为目标，不硬截断模型输出；复杂对比、空间分析或用户明确要求详细说明时允许超出。

### 上下文隔离

- RAG 文档片段继续作为主要事实依据。
- 真实 KG 路径继续进入提示词。
- `isMock=true` 的 KG 路径保留在响应元数据中供图谱展示，但不写入 LLM 的 KG 上下文，避免模型将演示关系表述为真实结论。
- 空间分析上下文只在 `spatialAnalysis.interpretation.spatialIntent=true` 时进入提示词。普通的构造、成矿或岩石问题即使检索到坐标，也不因空间数据而扩写正文。
- 演示 KG 提示由前端根据 `kgContext.isMock` 显示一次；后端不再向回答正文追加相同声明。
- 空间演示数据仍由空间分析摘要在需要时标注，不与 KG 演示声明混写。

## Markdown 容错

提示词优先要求无序要点，减少模型连续输出多个 `1.` 的概率。

前端 Markdown 渲染器同时保留容错：当有序列表被空行拆开时，读取原始编号并为新的 `<ol>` 设置正确的 `start`，保证 `1.`、`2.`、`3.` 不会全部显示为 `1.`。现有 HTML 转义和链接安全规则保持不变。

## 回答组件

### 正文

- 助手回答最大宽度由 700px 调整到约 820px，并受容器宽度约束。
- 正文字号从 14px 调整到 15px，维持适合中文长文的行高。
- 用户消息宽度和现有视觉设计 Token 保持不变。

### 渐进披露

以下内容改为原生 `<details>` 或等价的可访问折叠结构，默认关闭：

- `参考来源 · N`
- `本体推理 · N 类 / N 个实体`
- `空间分析 · N 个点 / N 条线`

展开后继续复用现有 `SourceCard`、OWL 证据行和空间统计内容，不丢失数据。

演示 KG 关系保留一个紧凑提示，位置靠近知识图谱，正文中不再重复。

知识图谱组件保持当前展开逻辑；用户已确认截图中的图谱缩小是手动滚轮造成，不属于本轮缺陷。

### 地图操作

一条消息只保留一个地图操作区：

- 按钮文案为“查看地图”。
- 可在按钮旁以弱化文字显示“108 处标注”或地图任务标签。
- 不再显示“完整地图”和“在地图上查看”两个不同入口。
- 不再在问答页显示“已自动执行”或自动创建内嵌地图。

## 地图跳转数据流

点击“查看地图”时：

1. 读取当前消息的 `spatialData`、`spatialAnalysis` 和 `mapPlan`。
2. 若消息已有 `mapPlan`，重新写入 `spatialTask`，确保点击历史回答时不会误用最新任务。
3. 若消息只有 `spatialData`，创建稳定的轻量计划：`query` + `fit-bounds`，计划 ID 由消息 ID 生成。
4. 将任务保存到现有 `sessionStorage` 快照。
5. 根据登录角色跳转到 `UserMap` 或 `AdminMap`，查询参数携带 `task=<planId>`。
6. `MapView` 继续使用现有 `applySpatialTask()` 加载数据、筛选条件和高级空间动作。

没有空间数据也没有地图计划的消息不显示按钮。路由失败时保留当前问答页，不清除消息数据。

## 删除范围

从 `QaView.vue` 删除：

- `AMapLoader` 与问答页地图专用 imports。
- `activeSpatial`、图层状态、覆盖物状态和第二个地图实例。
- 自动跟随最新空间回答的 computed/watch。
- 地图初始化、覆盖物渲染、图层切换、关闭内嵌地图等函数。
- 固定高 320px 的地图模板、兜底列表和全部相关 CSS。
- 自动跳转 `openFullMap` 的 watcher。
- `isDev`、`mockIndex`、`injectMock()` 和“示例空间数据”按钮。

若 `mockSpatialPresets` 删除引用后无其他消费者，则同步删除该开发专用导出和对应无效测试数据；正式空间 mock 数据、Neo4j 演示实体和地图页功能不受影响。

## 测试

### 后端

- 普通地质问题的提示词包含“直接结论、2 至 4 个要点、避免无关扩写”等约束。
- 提示词不再要求“关键地质实体”。
- mock KG 路径不出现在 LLM 上下文，真实 KG 路径仍存在。
- 非空间意图不注入空间分析上下文；空间意图仍注入。
- 流式与非流式回答均不再追加重复 KG 演示声明。

### 前端工具

- Markdown 对由空行分隔的 `1.`、`2.`、`3.` 保持正确起始编号。
- 轻量地图计划包含稳定 ID、`query` 和 `fit-bounds`。
- `spatialTask` 能保存消息数据，地图页能按 task id 消费。

### 前端组件与构建

- `QaView` 不再引用或创建 AMap。
- 开发和生产环境均不显示“示例空间数据”。
- 有空间数据的消息显示唯一“查看地图”按钮。
- 参考来源、本体推理和空间分析默认折叠并可展开。
- `npm test`、`npm run type-check` 和 `npm run build` 通过。

### 人工验证

使用问题：

```text
攀枝花钒钛磁铁矿受哪些构造控制？
```

预期：

- 回答先给结论，正文不再出现“关键地质实体”长列表。
- 演示关系提示只出现一次。
- 参考来源、本体推理和空间分析默认折叠。
- 问答页不出现大地图面板或“示例空间数据”按钮。
- 点击“查看地图”后进入正确角色的地图页，并显示该条回答对应的空间数据。
- 返回问答页后，原回答和折叠状态不会产生地图遮挡。
