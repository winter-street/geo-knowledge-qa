## 第 4 页：双路检索 — 详细设计（1.5 分钟）

流程图：

```
用户问题
  ├→ jieba 分词 → TF-IDF 向量化 → SQLite 余弦相似度 → Top-K chunks
  └→ Neo4j Cypher MATCH...CONTAINS → 实体 + 关系链
              ↓
         合并上下文
              ↓
      DeepSeek LLM 生成回答
              ↓
   前端答案 + SourceCard + KG 标签
```

代码片段（放一张截图即可）：
- Flask `server.py` `/search` 端点的核心逻辑（向量化 → 相似度 → 排序）
- 约 25 行，标注关键行

要点：
- 为什么两路？RAG 给精确片段，KG 给关系网络，互补
- 为什么 TF-IDF 而不是 BERT？中期先跑通，终期升级

## 第 5 页：知识图谱构建 — 详细设计（1.5 分钟）

流程图：

```
PDF 用地分类指南 → 正则匹配编码层级 → LandUse 节点（137 个，大类+中类）
PDF 编制指南 → 分段 → DeepSeek 提取概念 → 语义过滤 → Concept 节点（213 个）
                                                    ↓
                                     Neo4j（350+ 节点，490+ 关系）
                                                    ↓
                                    GraphView 力导向图可视化
```

代码片段：
- `extract_concepts.py` 的 LLM prompt 结构 + 三条过滤规则
- Neo4j schema：节点标签 + 关系类型 + 中文 display

要点：
- 用地分类用规则提取（确定性），规划概念用 LLM 提取（灵活性）
- 过滤规则是工程重点：去掉数字编码碎片、句首片段、名称粘连
